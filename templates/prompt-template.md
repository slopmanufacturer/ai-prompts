# Prompt Title

> One line on what it does — the thing you'd tell a friend.

**Category:** Coding / Writing / Learning / Productivity
**Best for:** Which models it works well on, or "any capable language model"
**Difficulty:** Beginner / Intermediate / Advanced
**Output:** What you get back (e.g. "Structured issue list", "A 600-word story")

## When to use it

Two or three sentences. The situation where this earns its place — and, just as
important, when *not* to reach for it. Honest limits are part of the format.

## Variables to fill in

Only include this section if the prompt has `[BRACKETS]`. One row per placeholder.

| Placeholder | What goes there |
|---|---|
| `[THING]` | e.g. an example of what the user should paste |

## The prompt

````
The prompt itself goes inside a fenced block so it copies cleanly.
Use quadruple backticks for the outer fence if the prompt itself
contains a triple-backtick block — otherwise triple is fine.
````

## Example

**Input:**

> What you actually sent — enough context that the output makes sense.

**Output:**

> A real excerpt of what the model gave back. Trimmed is fine;
> made-up is not.

## Notes

- The lines in the prompt that do the most work, and why.
- Known failure modes — when it falls apart, and how to recover.
- Anything you learned by running it more than once.

## Follow-up prompts

Optional. Two or three natural next messages once the first answer comes back.

- "First follow-up."
- "Second follow-up."

## Sources

Optional — only if the file makes claims that need backing up (benchmarks,
external datasets, papers). Link the primary source, not a summary.
